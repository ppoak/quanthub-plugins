# Factor Improve

运行前按[插件说明](../../README.md)准备项目环境。`<skill-root>` 指本 Skill 的安装目录，`<plugin-root>` 指插件根目录。

Evaluate 完成后，检视因子效果，以扣除成本后的 Top 多头收益为重点，同时考察 IC 与分层收益稳定性。用户认可当前结果时可直接进入 Publish；否则，找出值得改进的构造，并将具体方案交回 Design。

## 评估输入

阅读因子 README 的定义、经济机制和参数，以及全部声明列的 `config.json` 和 `overview.png`；以 `ic.csv`、`returns.csv`、`correlation.csv` 为依据。覆盖 `raw`、`neutralized`、`rolling_mean`，分别查看训练、验证和测试期，不能只看 README 摘要或表现最好的变体。

确认产物完整且对应当前定义和数据；缺失或过期先返回 Evaluate，数据与实现错误按原流程返工。结果说明见[评估产物](../factor-evaluate/references/evaluation-artifacts.md)。

## 效果判断

| 重点 | 判断依据 |
|---|---|
| IC 强度与稳定性 | 平均 IC、ICIR、滚动及分年度表现、方向一致性和有效样本量；判断是否依赖少数日期或单一行情 |
| 分层效果 | 沿既定方向比较各层成本后收益和净值，观察单调性、层间差距、极端层反转及跨时期稳定性 |
| Top 多头表现 | 成本后收益、回撤和换手；与同股票池、区间、持有期和成本口径的基准比较，区分市场上涨、空头端贡献和多头自身的选股收益 |
| 暴露与增量价值 | 比较原始、中性化和平滑后的结果，结合参考因子相关性，判断是否主要来自行业、规模暴露或已有信号 |

方向沿用训练期的选择。不设统一 IC 或收益门槛，按研究目标和可比基线判断。缺少基准或诊断数据时明确说明。

## 改进方向

从实际弱点出发，优先推荐能解释现象、改动最少的方案。下列方向用于形成假设，是否有效由后续对照评估决定。

| 发现的问题 | 优先考虑的构造改进 |
|---|---|
| IC 弱、分层差 | 复核经济机制和量纲，拆分混合信号，调整归一化或非线性表达，避免无依据叠加变量 |
| IC 波动大、方向反复 | 检查信号窗口与作用周期是否匹配，尝试稳健统计、平滑或衰减，观察稳定性改善是否牺牲响应速度 |
| 极端层反转、单调性差 | 定位异常值、近零分母和非线性关系；有依据时采用稳健缩放，或拆分两端不同的经济机制 |
| 多空表现好、Top 多头弱 | 分别检视两端贡献，拆出驱动多头上涨的正向信号，避免构造主要用于识别下跌股票 |
| Top 毛收益好、成本后弱 | 减少噪声和排名跳变，尝试平滑、衰减或更稳定的尺度；持有期调整另作对照，不能替代构造改进 |
| 中性化后明显衰减、与已有因子高度相关 | 分辨预期机制与附带暴露，考虑行业内比较或提取独立成分，并解释保留与剔除的经济含义 |

## 设计交接

在回复中给出以下内容，逐列交代结论，并突出最值得推进的改进：

- **问题与证据**：指出对应列、变体和时期，用指标或曲线说明弱点，区分已知事实与待验证原因。
- **具体方案**：写清修改后的公式或计算规则、输入字段及可见时点、窗口、方向与边界，解释预期改善及可能损失。不能只写“优化参数”或“增加过滤”。
- **对照方法**：保留当前版本为基线，尽量一次只改一个关键构造，明确改善目标；股票池、区间、执行价格、持有期与成本保持一致，口径变化单独比较。

构造与参数选择使用训练、验证期，避免无依据扫参。测试期用于报告样本外表现；若已据此提出改进，该区间对新方案已不再独立，下一轮须另留未使用的样本检验。

将方案交给 [Factor Design](../factor-design/SKILL.md) 更新 README 第 1–5 节，再按[因子工作流](../factor-workflow/SKILL.md)进入开发、审查与后续脚本阶段。受改动影响的验收须重新完成。
