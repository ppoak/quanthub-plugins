# 验证规范

用原始数据独立复算，核对它与 SQL 计算的因子值是否一致。验证须覆盖全部声明列。

## 结果怎么看

结论直接写入因子 README 第 6 节“因子验证”，替换上次的结果表，并更新对应验收项。脚本不另生成验证报告。结果表记录验证区间、样本数量、覆盖率、误差和失败原因。

检查已有数据时，还保留每列的两个文件：`audit.csv` 用于查看逐条差异，`config.json` 用于核对参数、状态和使用的数据。默认目录为 `$ARTIFACTS/factor_zoo/<factor_name>/<factor_column>/`。验证过程中的临时计算文件在结束后清理，结论保留在 README。

## 样本怎么选

先确认所用数据与当前因子定义匹配，检查方式见[因子数据身份](../../factor-protocol/references/data-identity.md)。

通常选取 2–5 个真实交易日和 20–100 只股票。脚本按固定顺序选样，同样的数据和参数应得到相同样本。滚动窗口所需的预热数据可以早于验证区间，结果只比较目标日期；横截面计算仍须保留全市场口径。

## 怎样算通过

逐条比较同一日期、同一股票的复算值和物化值：

- 两边记录完整对应，没有缺失或重复。
- 空值位置一致，非空值均为有限数。
- 数值差异不超过配置的容差；全空样本不能作为通过证据。

全部声明列通过才勾选验收项。失败时记录原因并以非零状态结束，查明原因、修复后重新验证，不能通过填零、删除失败记录或放宽容差掩盖错误。

进入评估前，须完成未来数据和时点可见性审查。对已有数据的检查失败、历史因子数据变化或旧结果的计算指纹缺失、不一致时，已有评估标为 `stale`，需重新评估。
